     Plan: Add Expense feature (Step 07)

     Context

     The /expenses/add route is currently a stub (app.py:194-196, returns plain
     text "Add expense — coming in Step 7"). This step replaces it with a real
     GET/POST flow so logged-in users can record a new expense, following the
     spec at .claude/specs/07-add-expense.md. It reuses the existing
     auth/flash/form/CSS conventions established in register/login and the DB
     query patterns in database/queries.py.

     Implementation

     1. database/queries.py — add create_expense

     Add a new function following the existing
     connection/try-finally/parameterised-query convention (see get_user_by_id,
     lines 10-16):

     def create_expense(user_id, amount, category, date, description):
         conn = get_db()
         try:
             cursor = conn.cursor()
             cursor.execute(
                 "INSERT INTO expenses (user_id, amount, category, date,
     description) VALUES (?, ?, ?, ?, ?)",
                 (user_id, amount, category, date, description),
             )
             conn.commit()
             return cursor.lastrowid
         finally:
             conn.close()

     2. app.py — replace the add_expense stub (currently lines 194-196)

     Implement GET/POST handler mirroring the structure of register/profile:
     - Import create_expense from database.queries
     - Require session.get("user_id"), else redirect to login (mirrors profile,
     app.py:153-154)
     - Define VALID_CATEGORIES = {"Food", "Transport", "Bills", "Health", 
     "Entertainment", "Shopping", "Other"} (matches categories already
     seeded/styled, see database/db.py seed data and style.css badge vars)
     - On GET: render expense_form.html
     - On POST: read amount, category, date, description from request.form
       - Validate amount: must parse as float and be > 0 (catch ValueError)
       - Validate category: must be in VALID_CATEGORIES
       - Validate date: must match ^\d{4}-\d{2}-\d{2}$ (reuse the same regex
     pattern style already used in profile, app.py:148)
       - description optional, .strip()
       - On any validation failure: flash(..., "error") and re-render
     expense_form.html (mirrors register's pattern, app.py:78-86)
       - On success: call create_expense(uid, amount, category, date, 
     description or None), flash("Expense added!", "success"), redirect to
     profile (mirrors login's post-success flow, app.py:122-124)
     - abort(405) for other methods (mirrors register/login)

     3. Create templates/expense_form.html

     Modeled directly on templates/register.html structure:
     - {% extends "base.html" %}, title block "Add expense — Spendly"
     - Reuse auth-section / auth-container / auth-card wrapper classes and
     auth-error flash rendering (register.html:7-20)
     - <form method="post" action="{{ url_for('add_expense') }}">
     - Fields, each in a .form-group with .form-input:
       - amount — <input type="number" step="0.01" min="0.01">
       - category — <select class="form-input"> with the 7 valid categories as
     <option>s
       - date — <input type="date"> (matches existing date input styling,
     style.css:787-800, used in profile.html:33-35)
       - description — <input type="text">, optional (no required)
     - Submit button with .btn-submit, label "Add expense"

     No changes needed to base.html, style.css, or the database schema — all
     required classes/variables already exist.
