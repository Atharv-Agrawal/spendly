     Implementation Plan: Step 02 — Registration

     Context

     The /register route exists as a GET-only stub that renders register.html.
     The form already has the right visual design and posts to /register, but
     the route doesn't handle POST yet, there's no create_user() DB helper, no
     password hashing on input, and no flash messaging. This step wires all of
     that up so new users can actually create accounts.

     ---
     1. database/db.py — add create_user()

     Where: After the existing seed_db() function.

     Logic:
     1. Call generate_password_hash(password) — already imported at the top of
     the file.
     2. Open a connection via get_db().
     3. Execute a parameterised INSERT INTO users (name, email, password_hash) 
     VALUES (?, ?, ?).
     4. Commit and return cursor.lastrowid.
     5. If SQLite raises sqlite3.IntegrityError (UNIQUE constraint on email),
     let it propagate — the route handler will catch it.
     6. Always close the connection in a finally block.

     Reuse: get_db() (line 8), generate_password_hash (already imported on line
     3).

     ---

     2a. Imports to add

     from flask import Flask, render_template, request, flash, redirect,
     url_for, abort
     Current import line only has Flask, render_template — extend it in-place.

     Also add create_user to the from database.db import ... line.

     2b. Set app.secret_key

     Add immediately after app = Flask(__name__):
     app.secret_key = "dev-secret-key"
     This is required for flash() to work. A hardcoded dev string is acceptable
     per the spec.

     2c. Upgrade register() — full POST logic

     Change decorator to methods=["GET", "POST"].

     GET branch: render template as before (no change).

     POST branch — validation sequence (short-circuit on first failure):

     ┌──────────────┬──────────────────────────────────┬───────────────────────┐
     │    Check     │            Condition             │     Flash message     │
     ├──────────────┼──────────────────────────────────┼───────────────────────┤

     │ length       │                                  │ least 8 characters."  │
     ├──────────────┼──────────────────────────────────┼───────────────────────┤
     │ 3. Password  │ password != confirm_password     │ "Passwords do not     │
     │ match        │                                  │ match."               │
     ├──────────────┼──────────────────────────────────┼───────────────────────┤
     │ 4. Duplicate │ sqlite3.IntegrityError caught    │ "An account with that │
     │  email       │ from create_user()               │  email already        │
     │              │                                  │ exists."              │
     └──────────────┴──────────────────────────────────┴───────────────────────┘

     On any validation failure: flash(message, "error") then return 
     render_template("register.html").

     Success path:
     1. Call create_user(name, email, password).
     2. flash("Account created! Please sign in.", "success").
     3. return redirect(url_for("login")).

     Fallback: abort(405) if neither GET nor POST (belt-and-suspenders, though
     Flask's method routing already handles this).

         <div class="auth-error">{{ message }}</div>
       {% endfor %}
     {% endwith %}
     The existing .auth-error CSS class (already defined in style.css) covers
     the visual styling — no CSS changes needed.
